Why a parser, not a blocklist

The same dangerous command, written five ways.

A regex that greps for rm -rf / is trivially dodged — by a quote, a hex escape, a variable, or a pipe. blast-radius removes quotes, decodes $'\x..', resolves static variables and walks substitutions, so it judges the command's meaning, not its spelling. Every line below is caught.

Evaluation

Measured on real data, not vibes.

Three corpora: a 100-command hand-labelled gold set for precision/recall, every shell command from 6,670 real SWE-agent trajectories (55,560 commands), and 12,607 human-written one-liners from NL2Bash as an independent robustness test.

Under the hood

A small shell parser, then a scope-aware effect model.

No machine learning, nothing to train, nothing to phone home. Every verdict is explainable down to the exact program, effect and path that triggered it.

01

Parse like a shell

A hand-written recursive-descent parser handles quoting, $'\x..' escapes, parameter expansion, $( ) / backticks, heredocs, pipelines, subshells, loops and functions.

02

Resolve the real program

Quote removal and static variable tracking recover the actual command — so r''m, "rm" and $X all resolve to rm.

03

Map effects to scopes

A declarative tool knowledge base turns each argument into an effect — read, delete, network, exec — on a path, placed into a virtual filesystem: project, home, system or root.

04

Judge, and explain

A verb × scope severity model yields allow / review / block, with a plain-English reason for each finding. It fails closed: anything it can't resolve becomes review.

drop-in guardrail · Claude Code PreToolUse hook
# deny destructive commands, ask before risky ones, allow the rest
from blast_radius import analyze

report = analyze(command, project_root=cwd)
if report.verdict == "block":
    deny(report.findings[0].message)   # e.g. "rm deletes /root — your entire home directory."
elif report.verdict == "review":
    ask_user(report.findings)             # surface the reasons, let a human decide
else:
    run(command)                       # no effects outside the project

Ships with a CLI (blast-radius "rm -rf build", exit code = severity) and a --hook mode that speaks the Claude Code hook protocol directly.

blast-radius Source & benchmarks README Built by Rishikesh Nair · MIT licensed

blast-radius is a static analyser and a defence-in-depth layer, not a sandbox or a guarantee. It reasons about a command's likely effects without executing it; a determined adversary or a highly dynamic command (one whose behaviour is decided entirely at runtime) can still evade static analysis, which is why anything unresolved is surfaced for review rather than silently allowed. Use it alongside least-privilege execution, not instead of it. The live demo runs the exact published analyzer in your browser via Pyodide; the benchmark figures are reproducible from the scripts in the repository.
